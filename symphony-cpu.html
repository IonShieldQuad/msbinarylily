Symphony — система команд и программы

Процессор Symphony собран снизу вверх — от одного NAND-вентиля до 32-битной системы команд. Здесь она целиком: кодировки, регистры, переходы, работа с памятью и пять программ, написанных на её ассемблере и прогнанных на самом процессоре.

Исходный технический документ, поэтому ниже он на английском. Публичного репозитория нет: процессор существует внутри игры Turing Complete как схема, а не как код. Схему и запись прогона можно показать по запросу.

Design notes

  • Fixed 32-bit instructions, 4-bit register fields, immediate variants sharing the opcode family (register 001xxxxx vs immediate 0011xxxx for ALU; 01xxxxxx for memory).
  • flags register written by cmp; 8 conditional jumps read it (signed vs unsigned comparison sets, plus equality).
  • sp is a general-purpose register used by convention as the stack pointer (see symphony programs — Hanoi uses push/pop/call/ret).
  • Persistent memory (pload/pstore) is non-volatile across the level — the RNG uses it to keep a seed.

Symphony Programs

Tower of Hanoi

Recursive solution using the stack: push/pop on sp, call/ret — the classic proof that the calling convention and stack work end-to-end. Uses in for N (number of disks), source, destination, and spare pegs; outputs each move followed by a GRB (grab) marker so the game engine executes them.

const NUM = r10
const SRC = r11
const DST = r12
const SPR = r13
const GRB = 5

start:
in NUM
in SRC
in DST
in SPR

call hanoi
jmp start

hanoi:

cmp NUM, 0
jne cnt
out SRC
out GRB
out DST
out GRB
ret
cnt:
push NUM
push SRC
push DST
push SPR

mov r1, DST
mov DST, SPR
mov SPR, r1
sub NUM, NUM, 1
call hanoi

pop SPR
pop DST
pop SRC
pop NUM

out SRC
out GRB
out DST
out GRB

push NUM
push SRC
push DST
push SPR

mov r1, SRC
mov SRC, SPR
mov SPR, r1
sub NUM, NUM, 1
call hanoi

pop SPR
pop DST
pop SRC
pop NUM

ret

Random Number Generator

A xorshift PRNG (shift amounts 13/17/5). The seed is persisted across runs via pload/pstore to persistent (non-volatile) memory at address 0 — so each run continues the sequence instead of repeating. Falls back to reading a fresh seed from input if the stored seed is zero.

pload r1, [0]
cmp r1, zr
jne cnt
in r1
cnt:
call rng
pstore [0], r1
out r1

jmp 0
rng:

push r2
push r3
push r4
push r5
push r6

lsr r2, r1, 13
xor r3, r2, r1
lsl r4, r3, 17
xor r5, r4, r3
lsr r6, r5, 5
xor r1, r6, r5

pop r2
pop r3
pop r4
pop r5
pop r6

ret

out r7   ; note: trailing line from the original session; harmless dead code

Letter Capitalizer

Capitalizes the first letter of each word. The key trick is the ASCII bit toggle: uppercase and lowercase letters differ by exactly one bit (0b00100000), so xor r1, r1, 0b00100000 flips case in a single instruction. A small state machine (r2 remembers whether we just saw a space) ensures only the first letter of a word is capitalized.

Capitalize:
start:
in r1

cmp r1, 0b00100000
jne cnt1
mov r2, 0
jmp out
cnt1:
cmp r2, 0
jne out
mov r2, 1
xor r1, r1, 0b00100000

out:
out r1
jmp start

Sorting Algorithm

Reads 16 values into RAM at 0x0100, sorts them in memory using load_32/store_32, then outputs the sorted list. Demonstrates addressing modes, immediate-address memory access, and the unsigned jge/jle comparison jumps. The inner loop is an insertion-sort variant that walks the window down and re-sorts on each new element.

Sorting:
start:
mov r1, 64
inloop:
in r3
sub r1, r1, 4
cmp r1, 0
add r2, r1, 0x0100
store_32 [r2], r3
jg inloop

mov r2, 0x013C

sort:
load_32 r4, [r2]
sub r2, r2, 4
load_32 r5, [r2]
add r2, r2, 4

cmp r4, r5
jge cnt

store_32 [r2], r5
sub r2, r2, 4
store_32 [r2], r4
add r2, r2, 12
cmp r2, 0x0140
jle cnt
mov r2, 0x0140
cnt:
sub r2, r2, 4
cmp r2, 0x100
jge sort

mov r1, 0
outloop:
add r2, r1, 0x0100
load_32 r3, [r2]
out r3
add r1, r1, 4
cmp r1, 64
jl outloop

jmp start

Game of Nim

Perfect-play strategy for Nim (take 1–3 cards). The key insight: r1 % 4 via and r3, r1, 3 (mod-4 on powers of two is a single bitwise AND). If r1 % 4 == 1 you're in a losing position (take 1, the safe move); otherwise take (r1 - 1) % 4 to restore the winning residue.

Nim:
start:
    in r1               ; read current number of cards
    cmp r1, 0           ; if no cards left, opponent took the last card and lost
    je end
    and r3, r1, 3       ; r3 = r1 % 4 (using bitwise AND with 3)
    cmp r3, 1           ; check if we are in a losing position (r1 % 4 == 1)
    je losing

    ; Winning position: take (r1 - 1) % 4 cards
    sub r2, r1, 1       ; r2 = r1 - 1
    and r2, r2, 3       ; r2 = (r1 - 1) % 4
    out r2              ; output the move
    jmp start           ; opponent reacts, read new number of cards

losing:
    ; Losing position: take 1 card (any legal move works, but 1 is safe)
    mov r2, 1
    out r2
    jmp start

end:
    nop
    jmp end             ; infinite loop to terminate cleanly
